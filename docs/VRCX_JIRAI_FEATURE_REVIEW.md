# VRCX-jirai 功能审查与 VRCMomo 移植计划

> 审查对象：[FuLuTang/VRCX-jirai](https://github.com/FuLuTang/VRCX-jirai)
>
> 审查日期：2026-07-31
>
> 本文只记录功能方向与安全边界，不代表 VRCMomo 已经移植了这些功能。

## 1. 结论

VRCX-jirai 是基于 VRCX 的个人魔改分支。它里面有一些适合 VRCMomo 的关系管理、活动统计和资料历史功能，但不能整仓库照搬：

- 一部分功能本来就是 VRCX 原版功能，不能写成 jirai 或 VRCMomo 的原创；
- 一部分功能依赖 VRCX 的桌面数据库结构，不能直接套进 Kotlin Multiplatform；
- 一部分功能会持续记录非好友、推断他人关系，隐私边界明显更敏感；
- 自动跟随实例、自动加入群组等行为不进入 VRCMomo 主线。

VRCMomo 的定位应当是：

> **以 VRCM Team 的 VRCM 为基础，面向移动端的、强调好友关系与回忆管理的独立延续项目。**

参考 VRCX / VRCX-jirai 的目的，是补足“好友管理”和“活动回忆”的信息层，而不是复制桌面端的追踪工具。

## 2. 贡献与来源归属

以后实现相关功能时，README、设置页和功能说明都要按下面的方式标注：

| 来源 | 应如何描述 |
| --- | --- |
| VRCM Team / 上游 VRCM | 应用基础工程、Kotlin Multiplatform / Compose Multiplatform 结构、登录认证、VRChat API 网络层、好友/世界/群组/通知、已有 Gallery 与关系网等上游能力 |
| VRCX 原版 | 关系网、共同好友、Dashboard、Gallery / ScreenshotMetadata、通知中心、笔记等原版已有思路或功能 |
| VRCX-jirai | 双人共同实例统计、关系时间轴、手动关系、Bio Diff、信息补全等该分支的实现思路；不把上游已有功能写成 jirai 独创 |
| VRCMomo | 新品牌、移动端 UI、主题与导航、Boop 与通知改进、后台观察开关、活动统计的 Kotlin 实现、VRCMomo 自己的导入/导出与隐私控制 |

移植时优先复用思路和数据定义，不直接复制大段实现。若未来确实复制了 MIT 授权代码，应保留原作者与许可证说明，并在对应文件或 NOTICE 中明确来源。

## 3. 推荐进入主线的功能

### 3.1 好友活动时间轴（P0）

VRCMomo 已经有本地 FriendActivityStats，包含：

- 最后见面时间；
- 见面次数；
- 一起游玩时长；
- 最近上线 / 下线时间；
- 最后活动时间。

下一步不需要复制 jirai 的完整图表，而是先做移动端可读的时间轴：

- 只展示本机实际观察到的记录；
- 明确显示“从开始观察后累计”，不伪造历史；
- 支持按好友、时间范围筛选；
- 统计卡片和列表优先于复杂图表；
- 没有数据时给出“需要开启观察并运行一段时间”的说明。

### 3.2 双人共同活动（P0）

建议做成“共同活动”而不是“关系推断”：

- 选择两个好友；
- 从本地已记录的活动中寻找共同实例；
- 显示共同出现次数、累计时长、最近一次共同出现；
- 只展示双方均有记录且时间重叠的片段；
- 对 private、unknown 或不完整的位置做脱敏和隐藏；
- 不显示“谁和谁关系更近”之类的自动结论。

第一版只依赖 VRCMomo 自己的活动缓存，不额外抓取陌生人数据。

### 3.3 Bio Diff（P1）

适合做成本地资料历史：

- 仅在用户打开好友资料或主动执行刷新时保存快照；
- 显示 Bio 的新增、删除和修改；
- 默认只保留有限数量的历史记录；
- 设置中可以关闭或清空历史；
- 不后台批量扫描陌生人。

### 3.4 手动关系与本地备注（P1）

允许用户自己建立“认识于某活动”“现实朋友”“创作伙伴”等本地标签或连线，但必须写清楚：

> 这是用户自己的本地备注，不代表 VRChat 官方关系，也不代表被备注对象的同意。

它不应自动从共同实例推断出来。

### 3.5 关系网 UI 重制（P1）

可以借鉴 jirai 的图例、社区颜色、手动关系样式和统计布局，但保持 VRCMomo 的三种配色、明暗模式和移动端可读性：

- 普通好友、收藏好友、手动关系使用不同但可访问的颜色；
- 关系图提供图例和筛选；
- 非好友节点默认不显示；
- 节点点击后能直接进入用户资料；
- 大图作为辅助，列表统计作为主信息。

## 4. 需要开关、默认关闭的功能

### 4.1 手动追踪非好友

可以作为实验功能，但必须满足：

- 用户手动输入或选择对象；
- 不支持批量导入；
- 默认关闭；
- 只记录公开资料与用户主动查看的数据；
- 限制刷新频率；
- 有清晰的隐私提示和一键清除入口；
- 不发送好友请求、不自动加入实例、不自动通知对方。

建议单独放在 codex/experimental-observation，不要混进当前稳定分支。

### 4.2 好友资料批量补全

可以做成手动操作：只针对好友或收藏好友，显示预计请求数量和进度，限制频率，支持中途停止，不在后台静默执行。

## 5. 不进入 VRCMomo 主线的功能

### 5.1 自动跟随 / 自动加入实例

不实现以下行为：

- 自动启动 VRChat；
- 自动加入好友所在实例；
- 自动重试进入私密或好友实例；
- 通过持续监测来决定是否加入他人位置。

这类功能会把“查看信息”变成“自动行动”，也容易造成骚扰、误入私人空间或违反平台规则。若未来仅为研究 API 行为建立实验分支，也必须默认不构建、不启用，并且不能进入公开 Release。

### 5.2 自动加入 Group

VRCMomo 不会因为安装或启动应用而自动加入任何 Group，也不会把加入 Group 作为功能前提。

### 5.3 关系推断和过度画像

不做“这两个人一定在一起”“谁在监视谁”“谁对谁最重要”等自动结论，也不对非好友长期记录位置、上线和共同活动。可以展示事实性的本地统计，但不替用户解释他人的关系。

### 5.4 多账号聚合

VRCX-jirai 的多账号 WIP 不能直接移植。VRCMomo 先保证单账号的缓存隔离、通知归属、前台服务生命周期、导入导出边界和数据删除，完成后再单独评估多账号。

## 6. 数据与隐私约束

所有关系统计功能都应遵守：

1. 数据默认只存储在本机；
2. 统计只反映应用实际观察到的时间段；
3. 不把缺失数据当作“没有发生”；
4. 不为补全统计而无限调用 VRChat API；
5. private / unknown 位置默认隐藏或模糊化；
6. 设置中提供观察开关、历史清除和导出；
7. README 与设置页面同时说明数据来源和限制。

## 7. 推荐开发顺序

### 稳定主线

1. 好友活动时间轴简化版；
2. 双人共同活动统计；
3. Bio Diff；
4. 手动关系 / 本地备注；
5. 关系网 UI 与筛选重制；
6. VRCX 数据导入格式调查；
7. VRCX 兼容导出格式设计。

### 实验分支

1. 手动追踪非好友；
2. 受限的好友资料批量补全；
3. 更详细的活动历史实验；
4. 只读的导入兼容性实验。

### 明确不做

1. 自动跟随和自动加入实例；
2. 自动加入 Group；
3. 大规模陌生人追踪；
4. 自动关系推断；
5. 多账号聚合（在单账号数据边界稳定前）。

## 8. 当前分支说明

本审查在 codex/vrcx-feature-review 分支进行。该分支先提交审查文档，不直接把敏感功能带入 codex/ui-foundation。

后续每个功能应使用独立分支，例如：

- codex/friend-activity-timeline
- codex/two-person-activity
- codex/bio-diff
- codex/experimental-observation

每个分支合并前都应补：数据来源说明、隐私开关和清除路径、测试、README 归属说明，以及不支持或不完整数据的提示。
